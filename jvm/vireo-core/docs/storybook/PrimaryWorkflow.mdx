# Primary workflow

A managed aggregate combines one entity, DTO, mapper, repository, and service configuration while Core preserves the shared CRUD lifecycle around them.

## Why it exists

Hand-written CRUD services tend to drift: one forgets soft-delete filtering, another skips keyword refresh, and another publishes an offline event before its transaction commits. `BaseService` owns those mechanics and exposes narrow template hooks for domain-specific validation and relation wiring. Use an ordinary Spring service when the workflow is not CRUD-shaped.

`EntityConfig` is immutable. Add a value such as `history(AppHistoryEntityType.PRODUCT)` only when the History artifact is installed and the aggregate truly requires an audit trail; application enums implement `HistoryEntityType` directly. Add relation-search fields only for valid entity paths.

Customize `validateCreateRequest`, `validateUpdateRequest`, `validateDeleteRequest`, `buildCreateDomain`, `applyRelations`, or `performDelete`. Do not override `create`, `update`, or `delete`; Core rejects that at service construction because doing so could bypass history and offline invariants.

For new endpoints, use `BaseRequestService` instead: its public operations are `create(CREATE)` and `patch(ID, PATCH)`, returning `RESPONSE`. Map relation IDs from writable requests and resolve them in `applyCreateRelations` / `applyPatchRelations`; return only relation display data from `RESPONSE`.
